# Tracks and side prizes

Fetched 2026-11-04. Source IDs resolve in [INDEX.md](INDEX.md). Prize values and names are exact; problem statements are paraphrased.

**Campaign targets:** Track 01, Code with Wispr, Best Blog. Tracks 02 and 03 are recorded for completeness.

## Baseline for every workflow track

No source sets a separate minimum bar per track. These apply to Tracks 01 and 02 through the challenge and FAQ. [S1, S5]

- At least one AI agent and one person complete a real task together in a team chat, connected through Switch.
- Switch is central, and the README shows how it was used.
- The Switch setup and workflow are built during the hackathon.
- Repo, demo video and README are submitted (public repo per DTA).
- Judged on the 30/25/25/20 rubric in [event.md](event.md).

**Required tech:** Switch. Any agent, and any of Slack, Teams, Discord, Telegram or Mattermost.

## Track 01: Best Business Workflow

- **Problem:** a practical workflow that uses Switch to help people and AI agents get work done.
- **Who:** technical and nontechnical participants, with any combination of people, agents and rooms.
- **Minimum bar:** the baseline above. Nothing extra is stated.
- **Prize:** see [event.md](event.md) question 2.

## Track 02: Best Personal or Creative Workflow

- **Problem:** use Switch and agents to simplify everyday tasks, manage personal projects, or realize creative ideas.
- **Minimum bar:** the baseline above. Nothing extra is stated.
- **Same project in both Track 01 and Track 02:** not addressed. See [event.md](event.md) question 6.

## Track 03: Best Core Contribution

- **Problem:** a meaningful code contribution to Switch's open source core: capabilities, performance, reliability or developer experience. Issues also exist for integrations and extensions.
- **Prize and judging count:** see [event.md](event.md) question 3.

**Minimum bar, stated on both sites:**

1. Only issues labelled `hackathon` count.
2. Comment with a short plan, then wait to be assigned before coding. WMD says to tag `@petr-sandbox`.
3. One person per issue.
4. Read `CONTRIBUTING.md`. A one-time CLA is signed on the first PR.
5. Link the issue with `Closes #number`.
6. An unassigned PR is not judged. Low-effort PRs (typos, formatting, unreviewed AI output) are not judged.
7. No activity for 48 hours may lose the assignment.

**Where the sites differ:**

| Rule | WMD | DTA |
|---|---|---|
| Concurrent work | Up to 5 open PRs, each for an assigned issue | One issue at a time |
| Start | Can start before Nov 4; PR open by Nov 7, 11:59 PM IST | Open the PR between Nov 4 and Nov 7, 11:59 PM IST |
| Spam | Spam removes you from the track | Not stated |

**Current state:** 63 open `hackathon` issues, and all 63 have assignees. [S11, `gh`, 2026-11-04]

## Code with Wispr (side track)

- **Problem:** build the Switch project by voice, speaking prompts, agent instructions and docs through Wispr Flow.
- **Prize:** `$500` for the best project built by voice. Listed on WMD only.
- **Stacking:** can be entered alongside any track.
- **Minimum bar:** a Wispr usage scorecard, which is a screenshot from Insights in the Wispr Flow desktop app, added at submission.
- **Judging criteria:** not published beyond "best project built by voice".
- **Details:** [sponsors/wispr-flow.md](sponsors/wispr-flow.md).

## Best Blog (side track)

- **Problem:** a published post about building with Switch: what was made, how it was set up, and what was learned.
- **Judged on:** clarity, accuracy, and usefulness to a first-time Switch user.
- **Stacking:** alongside a track or on its own. DTA says a post submitted with the project also enters this track.
- **Prize count:** one post on WMD, top 5 on DTA.
- **Publication venue and length:** not stated.
